# Сравнение методов тестирования ЛР 4

| Метод | Преимущество | Ограничение | Применение |
| --- | --- | --- | --- |
| Причинно-следственный анализ | Связывает совместные входные условия с HTTP-ответом и расчётом | Требует явно описанных правил | Таблица решений для скидок и порога BULK15 |
| Граничные значения | Находит ошибки сравнения и округления | Пропускает сочетания вдали от границы | 9999.99, 10000.00, 10000.01 и пределы количества |
| Эквивалентное разбиение | Сокращает число однотипных проверок | Ошибка в разбиении оставляет пробелы | Известный, неизвестный и отсутствующий код |
| Покрытие решений и условий | Показывает пройденные развилки и значения предикатов | Высокий процент сам по себе не проверяет правильность результата | Ветки выбора скидки, валидатор bool |
| Комбинаторное покрытие условий | Выявляет эффекты совместных условий | Число сочетаний растёт, а часть решений недостижима | Оба исхода порога для BULK15, классы кода скидки |
| Интеграционное тестирование | Проверяет контракт между модулями | Сложнее локализовать источник сбоя | REST → валидация → сервис расчёта → отчёт |

Рекомендуемый порядок: таблица решений, уточнение границ, затем проверка
переходов по отчёту coverage.py. Регрессионная проверка сохраняет пример
обнаруженного сбоя и запускается вместе с основной группой тестов через CI.
