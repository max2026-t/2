# Сравнение стратегий интеграции

| Стратегия | Преимущества | Недостатки | Подходящие проекты |
|---|---|---|---|
| Нисходящая | ранняя проверка API и пользовательского сценария | нужны заглушки нижних модулей | сервисы с важным внешним контрактом |
| Восходящая | вычислительное ядро проверяется первым | интерфейс системы появляется поздно | расчетные и библиотечные системы |
| Сэндвич | верхние и нижние уровни можно проверять параллельно | сложнее планировать средний слой | многоуровневые приложения |
| Риск-ориентированная | опасные места проверяются раньше | требуется предварительная оценка рисков | проекты с новыми технологиями |
| Функциональная | быстро появляется законченная функция | возможна временная дубликация | продуктовая разработка по сценариям |
| Т-образная | рано работает один сквозной путь | остальные функции остаются неполными | прототипы и проверка архитектуры |

Для варианта 19 выбрана нисходящая стратегия. В системе обработки заказов
важен стабильный REST-контракт, поэтому сначала был проверен маршрут API,
а еще не готовые модули расчета и отчета заменялись заглушками.
