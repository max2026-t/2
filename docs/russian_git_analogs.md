# Российские аналоги Git, включённые в Единый реестр российского ПО

Ниже — краткий обзор пяти отечественных платформ для работы с Git-репозиториями, которые прошли регистрацию в Едином реестре российского программного обеспечения Минцифры. Все они предназначены для замены зарубежных решений (GitLab, GitHub, Bitbucket) и обеспечивают технологическую независимость от санкционных рисков.

---

## 1. GitFlic

**Разработчик:** «РеСолют» (входит в «Группу Астра»)  
**Реестровая запись:** №15861  
**Назначение:** платформа для хранения исходного кода и совместной разработки, полнофункциональный аналог GitLab.

### Функциональные возможности
- **Репозитории и управление кодом:** поддержка Git-репозиториев, веток, тегов, слияний, форков, истории изменений, релизов.
- **CI/CD:** встроенный движок конвейеров (pipelines), агенты (runners) для Docker, Kubernetes, Shell/PowerShell.
- **Реестр пакетов:** хранение Docker, Maven, NPM, PyPI, NuGet, Composer, CRAN, Deb, RPM, Go, Julia и др.
- **Безопасность:** инструменты SAST, DAST, SCA для раннего обнаружения уязвимостей.
- **Управление проектами:** панели мониторинга, трекинг задач (Issues), статистика, вебхуки, уведомления.
- **Миграция и интеграции:** миграция из GitLab с сохранением истории, интеграция с Jenkins, SSO (OIDC, LDAP, SAML), Gitleaks, Jmix.

### Преимущества
- Гибкость развёртывания: облачный сервис (SaaS) или локальная установка (Self-hosted).
- Полная экосистема разработки в едином контуре: код, CI/CD, реестр пакетов, безопасность, управление проектами.
- Российская разработка, защищённая от санкционных рисков.
- Успешные внедрения в крупных компаниях (например, «Магнит»).

### Ограничения
- Функциональность ориентирована преимущественно на замену GitLab; для специфических сценариев GitHub могут потребоваться дополнительные доработки.
- Информация о поддержке некоторых нишевых инструментов (например, Git LFS) в открытых источниках ограничена.

## 2. GitVerse

**Разработчик:** АО «СберТех» (дочернее общество ПАО Сбербанк)  
**Реестровая запись:** продукт включён в Единый реестр российского ПО (реестровая запись №17511 от 17.05.2023 для продуктов Platform V, GitVerse запущен в 2024 г.)  
**Назначение:** AI-first платформа для совместной работы над исходным кодом, позиционируется как российская альтернатива GitHub.

### Функциональные возможности
- Совместная работа над кодом с использованием искусственного интеллекта.
- Хранение и версионирование репозиториев (на базе Git).
- Управление организациями и правами пользователей, работа с профилем и дашбордом (через компонент GITT в составе Platform V Works::SourceControl).
- Журналирование действий пользователей, блокирующий флаг при работе с запросом на слияние, отображение списка слитых веток.

### Преимущества
- Разработка от крупнейшего российского интегратора (СберТех), продукты которого сертифицированы ФСТЭК и соответствуют ГОСТ-56939.
- Значительная пользовательская база: более 100 000 пользователей на момент 2024 года.
- Интеграция с экосистемой Platform V (более 90 продуктов).

### Ограничения
- Публичная информация о функциональных возможностях ограничена: детали CI/CD, реестра пакетов, инструментов безопасности в открытых источниках представлены фрагментарно.
- Ориентация на экосистему Сбера может усложнить интеграцию с инфраструктурой других вендоров.

## 3. Deckhouse Code

**Разработчик:** компания «Флант»  
**Реестровая запись:** №27871 (дата решения — 06.05.2025)  
**Назначение:** инструмент для непрерывной разработки и управления жизненным циклом программного обеспечения, российская платформа управления кодом и CI/CD.

### Функциональные возможности
- Управление исходным кодом (Git-репозитории).
- Непрерывная разработка и управление жизненным циклом ПО (CI/CD).
- Гибкая система контроля версий и разграничения прав доступа.
- Интеграция с экосистемой Deckhouse (контейнеризация, оркестрация).

### Преимущества
- Включён в Единый реестр российского ПО.
- Поддержка отечественных операционных систем: РЕД ОС, Astra Linux, Alt Linux.
- Упрощённый переход с GitLab: «Флант» разработала инструменты миграции.
- Соответствие отраслевым стандартам безопасности.

### Ограничения
- Продукт ориентирован в первую очередь на пользователей экосистемы Deckhouse; для команд, не использующих эту платформу, порог входа может быть выше.
- Функциональность реестра пакетов и встроенных инструментов безопасности в открытых источниках описана менее детально по сравнению с GitFlic.

## 4. GitFlame

**Разработчик:** Передовая инженерная школа Университета Иннополис  
**Реестровая запись:** №21590 (дата решения — 20.02.2024)  
**Назначение:** сервис хранения репозиториев с версионным контролем исходного кода.

### Функциональные возможности
- Управление версиями кода, хранение репозиториев.
- Высокая надёжность и безопасность при работе с исходным кодом.
- Подходит как для коммерческих компаний, так и для государственных структур.

### Преимущества
- Разработан в российском ИТ-вузе (Университет Иннополис) при содействии Межотраслевого центра трансфера технологий.
- Используется крупными заказчиками: ПАО «Ростелеком», ООО «ВК».
- Включён в реестр российского ПО Минцифры.

### Ограничения
- Публичная информация о функциональных возможностях (CI/CD, реестр пакетов, анализ безопасности) ограничена; продукт позиционируется прежде всего как система хранения и версионного контроля.
- Экосистема интеграций и инструментов миграции в открытых источниках описана менее подробно.

## 5. Platform V Works::SourceControl (компонент GITT)

**Разработчик:** АО «СберТех»  
**Реестровая запись:** №17511 от 17.05.2023  
**Назначение:** сервис версионного хранения кода и конфигураций (VCS), включающий компонент GITT для работы с репозиториями.

### Функциональные возможности
- Работа и управление репозиториями.
- Поддержка аутентификации.
- Управление организациями и правами пользователей.
- Работа с пользовательским профилем и дашбордом.
- Журналирование действий пользователей, блокирующий флаг при работе с запросом на слияние, общий поиск на уровне проекта и группы.

### Преимущества
- Включён в реестр российского ПО.
- Разработан СберТех — аккредитованной ИТ-компанией с многолетним опытом; продукты сертифицированы ФСТЭК.
- Интеграция с экосистемой Platform V (более 90 продуктов).

### Ограничения
- Информация о функциональных возможностях в открытых источниках представлена в виде описания изменений по версиям и не раскрывает полный набор инструментов CI/CD, реестра пакетов и безопасности.
- Ориентация на экосистему Сбера.

## Выводы

Все рассмотренные продукты включены в Единый реестр российского ПО и могут рассматриваться как отечественные аналоги Git-платформ. Наиболее зрелым с точки зрения функциональной полноты выглядит **GitFlic**: он предоставляет не только репозитории, но и CI/CD, реестр пакетов, встроенные инструменты безопасности и механизмы миграции с GitLab. **Deckhouse Code** выделяется поддержкой отечественных ОС и тесной интеграцией с контейнерной экосистемой. **GitVerse** и **Platform V Works::SourceControl** развиваются в рамках экосистемы Сбера и могут быть предпочтительны для организаций, уже использующих продукты Platform V. **GitFlame** ориентирован на хранение и версионный контроль с акцентом на надёжность и безопасность, что подтверждается внедрением в «Ростелекоме».

При выборе конкретного решения рекомендуется учитывать:
- требуемый набор функций (CI/CD, реестр пакетов, анализ безопасности);
- необходимость миграции с существующих платформ (GitLab, GitHub, Bitbucket);
- совместимость с используемой инфраструктурой и операционными системами;
- наличие интеграций с другими корпоративными системами (SSO, трекеры задач, мессенджеры).
